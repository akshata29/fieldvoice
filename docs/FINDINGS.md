# Verified findings (research + smoke tests, 30 Oct 2026)

Foundry Local SDK 2.2.1 (Python), Windows 11 dev box (Core Ultra 7 165H, 64 GB, NPU). Timings from this box are **not
representative** of the field fleet (Dell Latitude 7220 Rugged Extreme: 8th-gen U-series Intel CPU, 8/16 GB LPDDR3,
UHD 620 graphics, no NPU, per Dell spec sheets) and are used for behaviour, not for sizing.

| # | Finding | Consequence |
|---|---------|-------------|
| 1 | Catalog is wide: Whisper tiny/base/small/medium/large-v3-turbo (0.13-1.3 GB), Parakeet-TDT-0.6B and Nemotron **streaming** ASR (~0.7 GB), Qwen2.5 (0.5-14B), Qwen3 (0.6-14B, `dq44` and Microsoft fine-tuned 0.6B variants), Qwen3.5, Phi-3/3.5/4-mini/4, Ministral-3-3B (4.7 GB, text+image), SmolLM3-3B, Gemma-4-E2B (text+image+audio in, 6 GB), Qwen3-Embedding. | Enumerate the catalog dynamically; never hard-code models. |
| 2 | The prototype's model was described to us as "GPT-3.5 mini". That name is not in the Foundry Local catalog; **Phi-3.5-mini** (3.8B, 2.6 GB) is, and it is the closest match we know of. | Worth confirming which model the current ~45 s prototype really uses, so the comparison baseline is the real one. |
| 3 | After execution-provider registration each model exposes NPU / GPU (OpenVINO) / GPU (WebGPU) / CPU variants. Auto-selection picked the OpenVINO **NPU** variant, which then **failed to load**. | Pin variants explicitly, self-test at startup, fall back to CPU. Test every variant on a real Latitude 7220. |
| 4 | Grammar-constrained output works through `response_format` (`json_schema` as an *object*, or `lark_grammar` with `%json`). The Python SDK's string-form `json_schema` raised "schema must be an object or boolean". On Qwen2.5-0.5B the constrained output had perfect structure but **mixed up/mangled pole and unit ids**, and was not faster (whitespace-heavy output). | Constrain structure only. Resolve ids and enums deterministically. Score the silent-wrong rate, not JSON validity. |
| 5 | Number rendering differs per engine: Whisper-tiny "pole 1 2 3", Whisper-base "pole 123", Whisper-medium "pole 1-2-3", Nemotron "pole one two three" (synthetic TTS audio). | Normalize numbers and match ids against the job's closed world, whatever the engine. |
| 6 | Streaming ASR (Nemotron live session), the clip fed in real time: first words 0.7 s after the speech starts, final text **0.19 s after the last word** (p50 of 5, quiet dev box, RTF 0.45). Parakeet rejected file `transcribe()`; Nemotron's file path runs through the live session. | Use live sessions for perceived latency - while the engine keeps up (RTF < 1). On a slower tablet the tail grows by about (RTF - 1) x the speech length: measure there. |
| 7 | The OpenAI-style clients (`get_chat_client`, live session) are deprecated and will be removed at the end of 2026. | Build on `ChatSession` / `AudioSession` (this repo does). |
| 8 | Azure embedded (on-device) speech: limited-access registration (Microsoft-managed customers), Windows 11+, 16 kHz mono PCM WAV only, SDKs C#/C++/Java/Python/Go, **no iOS**. | Windows-only comparator. Request access early. |
| 9 | Foundry Local SDK targets Windows/Linux/macOS (docs and CI matrix) - no iOS. ONNX Runtime GenAI has iOS build/packaging history and a Phi-3 sample, but its README lists iOS as roadmap; an open issue reports memory growth when prefilling tokens on iOS (#1540). | iOS is a time-boxed spike (see `ios-spike/`). |
| 10 | Foundry Local's Windows (Windows ML) SDK requires Windows 11 24H2 (build 26100) or later. | Confirm the fleet OS build. |
| 11 | **Language-model call latency is prompt prefill.** On a quiet dev box, controlled calls (the same one-token answer after a short and a long prompt; a one-token against a 64-token answer) give about 18 ms per prompt token for Qwen2.5-1.5B (6.5 ms for 0.5B, 34 ms for 3B, 32-38 ms for Phi and Ministral) and 0-0.2 s of session setup: prefill is about 90 % of a hybrid call. An identical prompt repeated is **not** cached. Generation is memory-bound: 78 tokens/s (0.5B), 32 (1.5B), 15 (3B), 14 (Phi-3.5-mini), 11 (Ministral-3-3B, Phi-4-mini). | Count prompt tokens; the cheapest call is the one the gate never makes. Expect 4-6x slower prefill on the 8th-gen tablet. |
| 12 | `ChatSession` keeps conversation turns only for native `MessageItem` requests (`turn_count`, `undo_turns`); the OpenAI-JSON path that carries `response_format` (the only way to ask for a grammar) is stateless - `turn_count` stays 0. The native item API has no grammar option. | A cached static prefix (system prompt + examples) cannot be combined with grammar-constrained output today. Worth a spike on native turns + a tool schema as the constraint. |
| 13 | The `prompt` field of an audio transcription request is silently ignored by `AudioSession` (identical transcripts with and without a prompt listing the job's asset ids). | No Whisper "initial prompt" biasing toward the day's ids through Foundry Local. Azure Speech phrase lists are the available biasing mechanism. |
| 14 | Whisper renders numbers differently per size on the same clip: base writes "pole 123", tiny and small "pole 1 2 3", medium "pole 1-2-3" (also "feeder 23-22", "sorry, 3-28"). The hyphenated form was not joined at first, so medium scored below small (89.2 vs 92.6 % id accuracy) until the normalizer learned it (94.1 %). | The normalizer must handle every style (it does; covered by tests). Add each new engine to the sweep and read its failures before trusting a ranking. |
| 15 | A small model that may answer `null` mostly does. With the allowed-value grammar plus a `null` alternative, Qwen2.5-1.5B answered `null` for 62 % of fields that were clearly stated in slang; forced to choose, it was right 80 % of the time. Asking "was it mentioned?" as a separate yes/no and the value as a forced choice recovered most of it (docs/RESULTS.md). | Separate abstention from classification; keep every model answer `needs_review`. |
| 16 | Nemotron streaming drops spoken-correction words: "sorry" / "wait" survived in 6 of 14 correction clips (Whisper: 13-14 of 14), so "pole 123, sorry, 328" arrives as one long number. Correction clips score 88.5 % against 97.4 % for Whisper-base. | If streaming is chosen for latency, make the id easy to fix on the review screen, or re-run Whisper on the finished audio as a second pass. |

Sources: Microsoft Learn (Foundry Local overview/architecture/get-started, embedded speech + limited access),
microsoft/onnxruntime-genai README and issues (#385, #923, #1143, #1148, #1316, #1484, #1540), foundry-local SDK source
2.2.1, and direct smoke tests run while the demo was being built.

Decode speed is bounded by memory bandwidth / model bytes, prefill cost scales with parameters x prompt tokens. For
planning only (not measurements): LPDDR3-2133 dual channel is about 34 GB/s peak, so a 2.6 GB model cannot exceed
~13 tokens/s and a 0.8 GB model ~40 tokens/s before real-world losses. Hence the design: fewer tokens, smaller model,
deterministic resolution first, LLM only for what is left.
